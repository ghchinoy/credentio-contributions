## In-Process Media Provenance in 3 Lines

Verify C2PA Content Credentials directly in your application without network round-trips or subprocess startup latency:

<Tabs>
  <TabItem label="TypeScript (WASM)" icon="seti:typescript">
    ```typescript
    import { CredentioValidator } from '@ghchinoy/credentio-wasm';

    using validator = await CredentioValidator.create();
    const report = await validator.validateBlob(fileBlob);
    console.log(`Status: ${report.badge.toUpperCase()}`); // 'SIGNED', 'UNSIGNED', 'INVALID'
    ```
  </TabItem>

  <TabItem label="Python" icon="seti:python">
    ```python
    from credentio import Validator

    with Validator(skip_trust_checks=True) as validator:
        report = validator.validate_file("photo.jpg")
        print(f"Status: {report.badge.value.upper()}")  # 'SIGNED', 'UNSIGNED', 'INVALID'
    ```
  </TabItem>

  <TabItem label="Go" icon="seti:go">
    ```go
    validator, _ := credentio.NewValidator(credentio.WithSkipTrustChecks(true))
    defer validator.Close()

    report, _ := validator.ValidateFile("photo.jpg", "image/jpeg")
    fmt.Println("Status:", report.Badge()) // "signed", "unsigned", "invalid"
    ```
  </TabItem>

  <TabItem label="Swift" icon="apple">
    ```swift
    let engine = CredentioNativeEngine(skipTrustChecks: true)
    let report = try await engine.read(url: URL(fileURLWithPath: "photo.jpg"))
    print("Status:", report.badge.rawValue.uppercased()) // "SIGNED", "UNSIGNED", "INVALID"
    ```
  </TabItem>
</Tabs>

## Core Performance Principles

Powered natively by [Google Credentio](https://mediaprovenance.googlesource.com/credentio/) (the C++ validation engine operating at scale across nearly 40 conformant C2PA-enabled Google products):

<CardGrid stagger>
  <Card title="Local-First Privacy" icon="laptop">
    Media assets never leave your local environment. Validation runs entirely in-process, eliminating external API dependencies and bandwidth costs.
  </Card>
  <Card title="Low Memory Footprint" icon="rocket">
    Maintains a small, bounded memory footprint when verifying large multi-gigabyte video files or high-resolution imagery.
  </Card>
  <Card title="Sub-Millisecond Speed" icon="random">
    Runs core verification in **3 to 5 milliseconds** per asset, avoiding the 50 to 100 ms overhead of command-line subprocesses.
  </Card>
  <Card title="Multi-Format Support" icon="document">
    Inspects embedded credentials in JPEG, PNG, WebP, AVIF, HEIC, MP4, MOV, MP3, WAV, FLAC, PDF, and Office documents.
  </Card>
</CardGrid>

## Unified Architecture

Each language binding shares the same underlying `extern "C"` binary bridge (`libcredentio_c` / `credentio.wasm`), ensuring consistent validation semantics and uniform output across all platforms:

```text
┌─────────────────────────┐ ┌─────────────────────────┐ ┌─────────────────────────┐ ┌─────────────────────────┐
│     TypeScript (WASM)   │ │     Python (credentio)  │ │     Go (credentio/go)   │ │    Swift (CredentioKit) │
│  - Isomorphic Emscripten│ │  - cffi dynamic binding │ │  - cgo native binding   │ │  - Actor-isolated Swift │
│  - Browser & Node.js    │ │  - Typed dataclasses    │ │  - Idiomatic Go structs │ │  - Static XCFramework   │
└────────────┬────────────┘ └────────────┬────────────┘ └────────────┬────────────┘ └────────────┬────────────┘
             │                           │                           │                           │
             └───────────────────────────┴─────────────┬─────────────┴───────────────────────────┘
                                                       │
                                     ┌─────────────────▼─────────────────┐
                                     │      Shared C-ABI Bridge Layer    │
                                     │   (libcredentio_c / credentio.wasm)
                                     └─────────────────┬─────────────────┘
                                                       │
                                     ┌─────────────────▼─────────────────┐
                                     │      Google Credentio (C++20)     │
                                     └───────────────────────────────────┘
```
